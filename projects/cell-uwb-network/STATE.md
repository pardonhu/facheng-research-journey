## 当前有效版本

- **应用源文件：**[min-gap-body.c](code/legacy-work/min-gap-body.c)。已生成完整工程见`code/firmware/platforms/nRF52832-MinGap/`与`nRF52840-MinGap/`。
- **当前拓扑：**C为中心（nRF52840）；A、B、D为叶节点。其他历史版本常以A为中心，不能沿用标签假设。
- **数据帧：**32 bit确定性测试数据＋16 bit芯片校验；不发送标准地址帧头和152 bit实验管理字段。芯片另加前导码、8 symbol定界符、21 symbol高速物理层帧头及48 bit纠错冗余。
- **主控接口：**DMA SPI，正式数据均为8 MHz；nRF52840用SPIM3，nRF52832用SPIM0。32 MHz探索未通过，不能把它写成正式设置。
- **接收路径：**双缓冲、先重开接收，再搬运和统计上一包；直接检查CRC成功缓冲标志。没有实现PPI优化。
- **排程：**一次广播安排一批300条，三块叶节点轮流占用时槽，每块100条。正式配置10000条，33个300条批次＋1个100条批次。
- **补发：**每批检查缺失项，对每项最多再请求4次；含补发的总时间逐批记录。
- **最后已知板状态：**测试结束后四块板均停止收发，保留MinGap测试固件；下次操作先核对连接与实际运行状态。

## 已被后续结果覆盖的说法

| 历史说法或配置 | 当前应如何使用 |
|---|---|
| 单条272 bit帧 | 历史组网实验使用；其中152 bit为自定义实验管理字段 |
| 120 bit常规短地址帧 | 有厂家示例依据、做过时间推算；本会话没有该格式的正式组网重测 |
| 约350 μs是厂家规定或硬件下限 | 错误。来自旧486 μs起始间隔减去约135.835 μs计算帧时长；旧软件还测得约303 μs处理路径 |
| 486 μs是实测最短值 | 错误。它是旧扫描档位中的程序设置 |
| 750 μs首节点延迟是必要开销 | 没有最小化实验支持，是当时的程序余量 |
| 最新程序已压缩所有等待 | 尚未。MinGap仍保留每批首数据时间戳1000 μs安排、批尾500 μs等待及补发回复500 μs |
| 72／28节点是UWB容量上限 | 错误。它们来自272 bit旧帧、每3或2节点重复一次完整流程的外推 |
| 高分辨率时间戳证明100 ms内无漂移 | 尚未测量相应长延迟漂移曲线 |
| 两板48 bit测试等于多节点广播验证 | 两板Raw48是逐条请求—回复；随后MinGap才完成三叶节点星型广播 |
