# 用户报告偏好

- 后续实验报告统一使用 Markdown（`.md`），无需生成 Word。
- 用直白的中文说明实验目的、硬件如何连接、数据从哪里来、计时起止、结果及其含义。
- 节点容量以“每个电芯每 100 ms 上报一次，中心能否收齐”为主要问题。
- 明确分开实体板实测、时间预算推算、尚未验证的网络假设。
- 聚合实验必须说明是否包含叶节点到中继的采集过程，不能把预先生成数据的发送时间称为完整组网耗时。
- 导师汇报集中于节点容量、可靠调度与优化收益；不把闪灯、芯片识别、两板基础连通当作研究成果。
- 多项实验汇总为一份带清晰编号的报告，方便用户逐项提问；给出指标的直白定义。
- 报告配上帧结构、发包时序、网络拓扑等示意图；每项实验围绕一个明确判断，用数据支持结论并说明下一步。
- 科研表达参考用户个人网站 https://pardonhu.github.io/ 中的科研笔记，仓库为 https://github.com/pardonhu/facheng-research-journey 。
- 解释实验变量时注明来源：用户指定、芯片规范、厂家示例、自编程序参数或实测结果；程序等待应列出设置位置和数值，不能统称硬件固定开销。
- 采用“短结论要点在前、配图紧随、必要解释在后”的报告形式；每张图支持一个具体判断。
- 统一使用“电芯数据”；参数名称写完整，例如“前导码长度64个符号”“叶节点计划回复延迟750 μs”，避免省略为“64符号配置”。
- 报告受众是通信领域导师。UWB、ms、μs、ns、Mbps等常用缩写和单位直接使用，无需解释全称或单位换算。仅对理解实验所必需的专用配置、参数和计时定义作简短说明，避免基础通信知识科普。
- 采用简练、准确的通信学术术语，使用“轮询”而非“点名”。重点写清参数名称、数值、来源、对照中固定和改变的条件，以及计时起点、终点和包含的操作。直接陈述测量条件和结果，避免绕口的否定、对比和防御性表述。
- 按“代码库与底层适配—帧结构与时间定义—组网/中继形式及轮询、广播调度—结果分析—容量结论”组织。删除实验日期、操作经过及面向用户的闲谈。
- 主报告采用最新、已验证且服务研究目标的统一实验设置。围绕调度方式、时延和节点容量组织，删除“早期程序”“后来修改”等开发历史叙述及跨版本混合比较。旧实验数据保留归档，需要历史对照时单独注明实际配置，不能把旧结果改称最新测量。
- 帧结构先展示厂商规定的字段顺序，再说明本研究的参数和数据格式。厂商结构、工程参考参数和本次修改分别标明；不得把本研究的字段设计或参数称为厂家默认值。
- 数据量统一使用bit，时延统一使用相应的ms、μs或ns。前导码等同步序列按实际定义注明长度及对应时长，不将同步符号直接等同于数据bit。
- 每张图必须有正式编号和caption；正文引出并讨论该图。图注说明图示内容、关键条件、计时或统计含义，以及实测、计算或示意的属性；引用厂家图或格式时标明来源。图内标题不能代替图注。
- 两类拓扑统一命名为“星型拓扑广播”和“树型拓扑两跳中继”，全文、标题、表格、图内文字和图注保持一致。树型拓扑两跳中继内部的调度方式称为“轮询”或“广播定时回复”；星型拓扑广播的轮询对照明确标为“同一星型拓扑下的轮询对照”。
- 时序图以向下倾斜的箭头表示从开始发送到完整接收的过程；处理与等待时间用Δt₁等符号标注，并在图注中逐项说明起止。注明时间轴是否按比例绘制，不把程序等待参数等同于实测完整间隔。
- 使用“实验参数设置”“测量方法”“实验结果”等直接、规范的章节标题。后续研究集中列在结论，删除正文中反复出现的“最小可用值待测”等过程性说明。
- 正文与附录中的每项实验都应完整交代实验名称、目的、设置、指标、结果、分析结论。设置写清设备连接、数据来源与数量、固定参数和对照变量；指标写清计时起止或统计分母；结果给出具体数值；结论解释结果对研究目标的意义。
- 引用代码库、论文、数据集时使用可核验的正式名称，例如“toolnail/UWB代码库”，避免“同学的代码库”等关系称谓，不根据转发关系推断作者。学术表述优先写明具体对象，减少代词。
- 每项实验均补充200、300节点的分析，写明分组大小、调度方式、计时范围、推算公式及是否满足100 ms；分别标注实测、按现有流程推算和协议扩展后的理想时间预算。

- 每个实验的第一句直接给出结论，随后列目的、设置和支持数据；例如“重传补齐缺失数据”“广播调度降低完整采集时延”。图内使用最短的可辨识标签，公共条件写在caption；避免在每个刻度重复拓扑或调度名称。
- 本轮汇报删除电芯数据量缩减实验；272 bit帧中152 bit实验管理字段的影响需明确。现有帧结构下的容量可按实测小分组流程推算，明确分组和平均耗时假设；120 bit帧重测后另行更新。
- 本次导师汇报删除全部附录，正文聚焦组网实现、轮询与广播调度的完整采集时延对照及主要耗时来源。

- 容量分析同时给出帧间隔（前帧结束到后帧开始）、相邻发包起始间隔（两帧开始之差）和完整采集时延；图中直接标明中文名称及数值。容量公式写清按连续时槽估算还是按完整小分组串行推算，并注明现有实测帧结构。

- 未执行的实验明确写“尚未实测”；拟采用的格式不能写成已实施设置。报告表头标明实测、时序计算或性能推算。精简帧后的容量推算需写明是否同步缩短起始间隔，以及保留的控制、处理和等待开销。
