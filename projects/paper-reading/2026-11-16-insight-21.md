# 让调度意图落到测量上：传感器覆盖、UWB 融合、图采样与模型选档

专项第 96–100 篇。一项 MobiCom 传感器调度设计、直接使用 UWB 与惯性观测的 CVPR 工作，以及三种可迁移的模型或抽样方法。本页末列出十份总结的入口，便于以后按具体问题查找论文、实验写法和工具。

## IoT-Brain

**两条路线都说得通时，先查下一段能不能走**

Zhaomeng Zhou、Lan Zhang、Junyang Wang、Mu Yuan、Junda Lin、Jinke Song，*IoT-Brain: Grounding LLMs for Semantic-Spatial Sensor Scheduling*，MobiCom 2026，375–390 页。[正式论文](https://doi.org/10.1145/3795866.3796695) · [作者全文](https://arxiv.org/html/2604.08033v1)

**设计判断。** 调度校园传感器时，地名能指向多个出口。作者在 §4.3 第 7 页举例：系统查到图书馆有多个有效出口后，再查每个出口能否通往查询指定的下一站。这个问题把有歧义的地名变成一条可由场地图核对的连接。§4.4 第 8 页才调用集合覆盖程序，将已确认的路径分配给能覆盖各段的传感器。读者可以分别检查两件事：路线可否通行，这些设备合起来能否看全。前一步要用当前的场地资料，后一步要用每个传感器实际覆盖的范围。[§4.3–4.4](https://arxiv.org/pdf/2604.08033#page=7)

**真实取舍。** §6.2 用 587 条标注轨迹比较校园 Wi-Fi 摄像设备的调度方式。第 12 页表 2 中，开启所有候选设备的并行方案完成率为 65.64%，表列传输数据量 0.540 GB；IoT-Brain 为 49.84% 和 0.131 GB。结果同时呈现付出与所得：并行方案的传输量约为后者的 4.1 倍，任务完成率也高出 15.80 个百分点。这里 GB 度量的是数据量。论文提供实现及 TopoSense-Bench 演示版。[实验表 2](https://arxiv.org/pdf/2604.08033#page=12) · [作者实现](https://github.com/houqiii/IoT-Brain)

**原创无线算例。** 设一辆带测试信标的小车经过仓库 A、B、C、D 四段，每段只需一次可接收记录。实测网关一覆盖 A、B，网关二覆盖 B、C、D，网关三只覆盖另一条支路。查清小车所走的通道后，一、二号的覆盖并集含全部四段；任一网关最多覆盖三段，所以至少要两个。若任务改为双站同时接收以校验时钟，现有组合仅在 B 段满足，不能直接复用这个两站答案。这个手算对应一次接收的覆盖需求，未做场地实验。

**原创英文改稿。** 初稿 “The language model chooses the best gateways for the route.” 改为 “We first check which exit connects to the next waypoint. For that verified route, we select two gateways whose measured coverage spans all four segments.” 去掉含义不清的 *best*，把路线证据、覆盖依据和需要几台设备写进同一个例子。

## UMotion

**同一次 UWB 测距偏离惯性预测，该给它多大权重？**

Huakun Liu、Hiroki Ota、Xin Wei、Yutaro Hirao、Monica Perusquia-Hernandez、Hideaki Uchiyama、Kiyoshi Kiyokawa，*UMotion: Uncertainty-driven Human Motion Estimation from Inertial and Ultra-wideband Units*，CVPR 2025，7085–7094 页，DOI 10.1109/CVPR52734.2025.00664。[CVF 出版记录](https://openaccess.thecvf.com/content/CVPR2025/html/Liu_UMotion_Uncertainty-driven_Human_Motion_Estimation_from_Inertial_and_Ultra-wideband_Units_CVPR_2025_paper.html)

六个佩戴节点提供惯性观测和十五组节点间距离。§3.3–3.4 的单向时序网络估计姿态及其不确定性，滤波器用相对加速度推进节点间的位置与速度，再用 UWB 距离和人体几何约束更新。一帧中某对节点可能被身体挡住，作者便根据该链路的视距情况调整测距协方差。网络给出的姿态也有误差：将姿态分布的采样点送入人体模型，可以得到节点相对位置的均值与协方差，防止把模型预测当成尺子。实现中对这项位置协方差另乘 10，补偿模型过度自信。作者给出了真实距离、合成距离的独立评估入口及训练权重。[原文 7088–7090 页，式（4）、（13）–（18）](https://openaccess.thecvf.com/content/CVPR2025/papers/Liu_UMotion_Uncertainty-driven_Human_Motion_Estimation_from_Inertial_and_Ultra-wideband_Units_CVPR_2025_paper.pdf#page=4)、[作者固定版本评估入口](https://github.com/kk9six/umotion/blob/6213c32433c34200d6d7de262eda36d84cedbafd/README.md#L59-L81)

读结果要区分测到了什么。图 4 在 TotalCapture 上注入与视距有关的模拟噪声，原始节点间距离的平均绝对误差为 9.20 厘米，联合惯性、测距和姿态后为 2.42 厘米。另在含真实 UWB 的 UIP 测试集，作者校准距离后衡量关节位置（表 2）：UMotion 为 10.33 厘米，UIP 方法为 10.65 厘米。前一项是节点间距离，后一项是关节位置。[原文 7090–7092 页，表 2、图 4](https://openaccess.thecvf.com/content/CVPR2025/papers/Liu_UMotion_Uncertainty-driven_Human_Motion_Estimation_from_Inertial_and_Ultra-wideband_Units_CVPR_2025_paper.pdf#page=7)

**原创组网算例。** 在带铰链的小车上装两个 UWB 节点。惯性与机构模型预测两点相距 0.52 米，标准差 0.10 米；无线链路报告 0.82 米。用独立、零均值误差的一维线性更新演示：若通视时测距标准差为 0.05 米，测距权重是 $0.10^2/(0.10^2+0.05^2)=0.8$，更新值为 0.76 米；挡板介入后若标准差为 0.20 米，权重降为 0.2，更新值为 0.58 米。残差相同，两次采样条件不同。若持续出现正向偏差，应再估计偏差；调低权重本身不能把有偏测量校正到真值。本例用于解释权重，没有复现论文的非线性滤波器。

**原创英文改稿。** 初稿：“The filter corrects noisy UWB measurements with the motion estimate.”

改后：“We retain the radio range and the motion prediction as separate observations. When the panel blocks the radio path, we increase the range variance using calibration data from that condition. We report the resulting distance error separately from the position error of the articulated nodes.”

## 4D-GS

**场景里只有部分物体在动，哪些量可以跨时刻复用？**

Guanjun Wu、Taoran Yi、Jiemin Fang、Lingxi Xie、Xiaopeng Zhang、Wei Wei、Wenyu Liu、Tian Qi、Xinggang Wang，*4D Gaussian Splatting for Real-Time Dynamic Scene Rendering*，CVPR 2024，20310–20320 页，DOI 10.1109/CVPR52733.2024.01920。[CVF 出版页](https://openaccess.thecvf.com/content/CVPR2024/html/Wu_4D_Gaussian_Splatting_for_Real-Time_Dynamic_Scene_Rendering_CVPR_2024_paper.html)

若逐帧重建一个有运动物体的房间，静止部分也会随时间重复存储。§4.1–4.2 只保存一组基准三维高斯基元和一个随时间变化的形变场。输入某个基元的中心位置与所求时刻，从 $xy,xz,yz,xt,yt,zt$ 六组平面提取特征，再由轻量网络输出位置、旋转和尺度的变化。给定相机位姿，就可把此时的基元投影成对应画面。这种参数组织允许同一区域的基元共享运动信息，且无需给每个基元逐帧存坐标。作者开放了平面查询和按时刻生成形变的具体实现。[正文图 3、§4.1–4.2](https://openaccess.thecvf.com/content/CVPR2024/papers/Wu_4D_Gaussian_Splatting_for_Real-Time_Dynamic_Scene_Rendering_CVPR_2024_paper.pdf#page=3)、[平面查询](https://github.com/hustvl/4DGaussians/blob/843d5ac636c37e4b611242287754f3d4ed150144/scene/hexplane.py#L73-L110)、[形变计算](https://github.com/hustvl/4DGaussians/blob/843d5ac636c37e4b611242287754f3d4ed150144/scene/deformation.py#L97-L135)

§5.1–5.2、表 1 在 D-NeRF 合成动态场景、800×800 像素、单张 RTX 3090 的设置下报告 34.05 dB 的图像峰值信噪比和 82 帧/秒。前者检验生成画面与参考画面的接近程度，后者计量训练后渲染速度。换成无线传播模型，还需要射频观测来确定材料和路径强度；离线拟合出的时刻间变化也不能直接证明未来预测能力。[原文 20314–20315 页，表 1](https://openaccess.thecvf.com/content/CVPR2024/papers/Wu_4D_Gaussian_Splatting_for_Real-Time_Dynamic_Scene_Rendering_CVPR_2024_paper.pdf#page=6)

**原创组网算例。** 在一维测试线上，发射机位于 0 米、接收机位于 4 米，活动反射板从 6.0 米移到 6.3 米。两端固定，直达路径始终长 4 米；经板反射的路径则由 $6+2=8$ 米延长到 $6.3+2.3=8.6$ 米，按每纳秒约 0.30 米计算，反射峰应约晚 2 纳秒。可在已采集时段内复用固定路径，只用形变模型更新随反射板移动的候选峰，再用独立 UWB 观测查验峰的时间和强度。这个算例假设单次反射可辨，真实环境还可能出现遮挡、路径消失或新路径。

**原创英文改稿。** 初稿：“We update the entire channel map as the panel moves.”

改后：“We retain the fixed direct path and update the reflected path using the estimated panel position. A 0.30 m displacement in this geometry changes the reflected path length by 0.60 m. We compare the implied delay shift with a held-out impulse response before assigning the moving peak to the panel.”

## STREAM-UGS

**从邻居表随机走两步，会不会抽到过多三角形？**

Yann Bourreau、Marco Bressan、T-H. Hubert Chan、Qipeng Kuang、Mauro Sozio，*Efficient Streaming Algorithms for Graphlet Sampling*，NeurIPS 2024，DOI 10.52202/079017-0634。给定无向图的一份可重复扫描的边表，目标是使每个由 $k$ 个顶点组成的连通诱导子图都有相同抽中机会。采样单位是具体顶点集合，三角形、链等形状出现的样本比例应反映它们各自在图里有多少。[会方记录](https://proceedings.neurips.cc/paper_files/paper/2024/hash/23d64d26abb5a0e9f2014cfcc700f82a-Abstract-Conference.html)

**原文与工具。** §3 先按近似度数排序，再将每个可能的子图归到其中排在最前的顶点名下。一次试验先抽这样一个根顶点，沿当前集合的边界随机添点，直到有 $k$ 个点。不同候选集合的生长路径数、每一步可选的边数都可能不同，作者于是计算候选的提出概率，以相应的接受概率校正偏差，输出被接受集合的全部内部边。实现中 `RAND_GROW_fast` 和 `PROB` 分别负责生长和接受判断。§5 图 2 统计大图的扫描次数、内存和取得 100 个样本所需的试验数。该方法用反复读取边表换内存，活链路变化时需要先固定本次统计所对应的拓扑快照。[原文 §3、§5](https://proceedings.neurips.cc/paper_files/paper/2024/file/23d64d26abb5a0e9f2014cfcc700f82a-Paper-Conference.pdf) · [作者采样实现](https://github.com/l2l7l9p/UGS-Streaming/blob/b9fa15d74143761c5155cfd04b1bb70f772a156b/streaming.py#L254-L339)

**原创无线算例。** 节点 A、B、C 两两相邻，D 只连 C。全部连通三点组是 ABC、ACD、BCD，以这些组为单位等概率采样时，三角形占 $1/3$。现在改为等概率抽一对共用中心节点的边，再查看三个端点之间的所有链路。在这个图里一共有五对这样的边，三对属于 ABC，故观察到三角形的概率变成 $3/5$。在这个小例里，可以让三角形候选只以 $1/3$ 的概率通过，两种链候选总是通过；接受之后三个顶点组各占 $1/3$。这个手算校正针对上述两边采样器；原算法按自己实际的生长概率校正。它还能说明为什么不能直接用随机两跳记录的三角形占比评价邻居间的冗余链路。

**原创英文修改。** 初稿 “Randomly sampled two-hop paths reveal how common triangles are.” 改为 “We estimate triangle prevalence among connected three-node sets. Uniformly sampling pairs of incident links would count each triangle three times and each open chain once. In this snapshot, that changes the estimated fraction from one third to three fifths.” 改稿先指明分母，再指出一次采样动作会怎样改变这个分母下的比例。

## MatFormer

**同一个模型怎样给出中间一档计算量？**

Devvrit、Sneha Kudugunta、Aditya Kusupati 等人的 *MatFormer: Nested Transformer for Elastic Inference* 发表于 NeurIPS 2024。作者面对的部署问题是，两台设备可用的内存和计算时间不同，分别训练几个固定大小的模型以后，仍可能有设备的预算刚好落在两档之间。§3.1 式（1）让较小前馈层使用大层中前一部分隐藏单元，输入、输出维数不变，两个投影矩阵跟着取相同大小的子矩阵。§3.2 在训练步骤中抽取宽度档，让小档也能在自己的宽度下完成预测。[会议论文](https://proceedings.neurips.cc/paper_files/paper/2024/hash/fe066022bab2a6c6a3c57032a1623c70-Abstract-Conference.html) · [第 4–5 页，式（1）–（2）](https://proceedings.neurips.cc/paper_files/paper/2024/file/fe066022bab2a6c6a3c57032a1623c70-Paper-Conference.pdf#page=4)

**作者如何从固定档位走到中间预算。** §3.3 在各层选相邻的宽度，让浅层稍窄、深层稍宽，从同一套权重取出新的组合。§4.2.1 把“设备装得下的最大独立模型”和“从嵌套模型中取出、同样装得下的模型”放在同一预算下比较。以参数上限 50M 的 B/16 图像分类为例，作者报告后者的 ImageNet-1K 准确率约高 0.8 个百分点。选取具体组合仍使用验证集。作者项目提供 MatLM 语言建模实验的简化复现代码；这里的数值来自原论文的视觉实验。[第 9 页，§4.2.1](https://proceedings.neurips.cc/paper_files/paper/2024/file/fe066022bab2a6c6a3c57032a1623c70-Paper-Conference.pdf#page=9) · [作者 MatLM 公开实现](https://github.com/devvrit/matformer/tree/44dc039e6eef2712347716023b83d23fcfa5d788)

**原创 UWB 算例。** 网关用两层模型给每段信道观测做链路状态分类。假设每层输入、输出宽度都是 4，隐藏宽度可取 4 或 8。一个位置在一层的两个线性投影合计有 $2\times4\times h$ 次乘加。两层都窄为 64 次，都宽为 128 次。前窄后宽得到 96 次，刚好用上一台中档设备留给这两个前馈层的预算。算的是每个位置的前馈乘加数，注意力、激活、访存和无线收发另计。研究时可以在相同链路日志上分别检查三个档位对遮挡的漏判率，再实测各自时延。若把“窄和宽都能识别的链路”当成协议可靠性的依据，还需要真实接收记录。本次只演算网络结构，未部署分类器。

**原创英文改稿。** 初稿 “The small network fits the gateway’s budget and performs like the large one.” 改为 “Using width four in the first layer and width eight in the second requires 96 feed-forward multiply–accumulates per input position. This fits the assumed budget between the two uniform-width models. We would evaluate missed blockage events at each width before choosing a configuration for the gateway.” 第一项是可以从结构算出的开销，最后一项是选档仍需回答的性能问题。

## 第十个十篇的解题思路

**网络里有几台设备看见过目标，与某一时刻有几台同时看见它，是两个问题。** IoT-Brain 让语言模型借场地图消除路径歧义，选哪些设备则交给可以核验的覆盖条件。UMotion 说明，即使链路提供了距离，它能给最终位置增加多少信息也随遮挡而变。对一个经过 A、B、C、D 四段的测试信标，可以先用日志列出各段能看到它的网关，再为“记下这次经过”和“双站对时”分别生成计划。后者还需要检查两台网关的有效接收窗口是否重叠。可沿用语言模型解析意图、程序核查覆盖的分工；需要保留的量包括所需站数、同时性、容许时间差和实际收到的带时间戳记录。[IoT-Brain](#iot-brain) · [UMotion](#umotion)

**压缩之前先写清要回答什么，许多工具可以在这里分开用。** 如果网关以后必须逐项恢复原始状态，就可研究 LM-GC 的共享概率模型和无损编码；只需估计各锚点报告了多少次异常，可以考虑 Lego Sketch 的固定大小摘要；要研究邻居之间有多少三角形，STREAM-UGS 表明按路径随机采样会给同一个三角形多次入选机会。三个工具都能面对大量数据，各自保住的是原始序列、频数线索和按指定单位抽取的局部拓扑。一个实用组合是保留一小段可回放的完整日志，用它检查频数估计以及拓扑抽样各自在什么条件下偏离真值。[LM-GC 与 Lego Sketch](2026-11-16-insight-20.md) · [STREAM-UGS](#stream-ugs)

**时间上的复用，依赖这个量在两次操作之间到底有没有变。** 两条流交接后，单流速率会变化，终端总速率却可能维持；一块反射板移动后，直达几何保持原样，反射路径会变；一次调度后，已经收到的交付确认能排除一部分队列状态。这三个案例分别来自网络测量、动态场景建模和提前计算。写实验段时，可以先给两种解释在当前曲线上的共同预期，再安排一次交接、一次可控移动或一个带时戳的确认事件，让它们给出不同预测。[Dissecting the StarLink 与 EAGLE](2026-11-16-insight-20.md) · [4D-GS](#4d-gs)

**少算了一部分，接下来最该测的是哪一部分？** SAST 减少要彼此比较的观测位置；MatFormer 调整每个已处理位置在前馈层中经过的隐藏单元。这两项可以组合，但一次改变两个维度会让误差来源难分。在网关链路状态分类的设想中，可以先固定模型宽度改候选位置，观察弱路径是否被漏掉；再固定候选集合改宽度，观察已留下的弱路径能否被分辨。算出的格对数、前馈乘加数和设备时延分别报告。这里的无线组合尚未部署。[SAST](2026-11-16-insight-20.md#sast) · [MatFormer](#matformer)
