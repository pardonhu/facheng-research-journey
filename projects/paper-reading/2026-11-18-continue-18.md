# 2026-11-18 追加研读 18：保持量与提前准备，第六个十篇总结

新读FlexiViT与RANPilot，分别检查改变输入粒度时应保持的计算量，以及已知系统变更怎样让准备工作提前进行。FlexiViT发表于2023年6月，作为基础工具补充保留，已超出以当前日期计算的滚动三年窗口；RANPilot在该窗口内。末尾总结追加研读第51–60篇次。

## FlexiViT

Lucas Beyer、Pavel Izmailov、Alexander Kolesnikov、Mathilde Caron、Simon Kornblith、Xiaohua Zhai、Matthias Minderer、Michael Tschannen、Ibrahim Alabdulmohsin、Filip Pavetic，*FlexiViT: One Model for All Patch Sizes*，CVPR 2023，pp.14496–14506，DOI [10.1109/CVPR52729.2023.01393](https://doi.org/10.1109/CVPR52729.2023.01393)。[CVF 会方页面](https://openaccess.thecvf.com/content/CVPR2023/html/Beyer_FlexiViT_One_Model_for_All_Patch_Sizes_CVPR_2023_paper.html)；[正文 PDF](https://openaccess.thecvf.com/content/CVPR2023/papers/Beyer_FlexiViT_One_Model_for_All_Patch_Sizes_CVPR_2023_paper.pdf)；[补充材料](https://openaccess.thecvf.com/content/CVPR2023/supplemental/Beyer_FlexiViT_One_Model_CVPR_2023_supplemental.pdf)。

这项工具允许一组视觉模型权重在不同分块大小下运行，用不同的 token 数量适配计算预算。迁移到无线处理时，可探索同一个 CIR 模型在不同分块粒度下复用；核心问题是输入投影怎样随粒度变化，以及哪些信息无法通过改权重恢复。

### 六项研究卡片

- **问题：** ViT 的分块越小，token 越多，通常需要更多计算；固定分块训练的模型，推理时直接换分块往往明显失准（§3.1–3.2，PDF p3，论文 p14498，Fig.3）。
- **缺口：** 直接插值输入投影权重，即使同时放大输入，也会改变投影响应；仅让权重数组尺寸对上，没有保持原来计算的量（§3.4，PDF p4，式1–3）。
- **观察：** 把重采样写成线性映射 $B$ 后，保持响应等价于要求 $B^T\hat\omega=\omega$，可以据此求新权重。
- **方法：** 训练时随机选择分块大小，共享主干参数；输入投影采用 PI-resize，即 $\hat\omega=(B^T)^+\omega$，位置编码按新网格调整（§3.3–3.4，算法1、式4）。
- **证据：** Fig.4 保持 784 个图像 token，将输入由 $224^2$、分块8改为 $448^2$、分块16；PI-resize 的 ImageNet-21k precision@1 为52.3%，普通插值为12.8%，原始设置为52.4%（补充材料 p17，Table12）。
- **范围：** 对同一信号的满列秩上采样可精确保留该线性投影；降采样通常损失信息，其最优权重依赖输入分布。改变原始输入的分块方式也不能由这个局部等式推出整网输出相同。

### 工具动作与实现入口

输入是图像、选定的分块大小和一套共享模型权重。训练过程随机选择分块大小，按需生成对应投影权重和位置编码，再执行通常的前向与反向计算。部署时选择不同分块，可以输出分类结果或供下游任务使用的特征；原始图像尺寸不必因此改变。

作者在 [big_vision 项目页](https://google-research.github.io/big_vision/big_vision/configs/proj/flexivit/) 发布预训练权重、训练配置以及一个公开复现运行的日志入口。本次检查提交 `0127fb6b337ee2a27bf4e54dea79cff176527356` 的 [模型代码](https://github.com/google-research/big_vision/blob/0127fb6b337ee2a27bf4e54dea79cff176527356/big_vision/models/proj/flexi/vit.py)：`resample_patchemb` 对每个基向量调用与数据预处理一致的双线性 resize，拼成矩阵 $B$，再计算 `pinv(B.T)` 作用于每个输入通道与输出特征的投影核。实现基于 JAX/Flax，并调用 TensorFlow 的图像 resize，训练还需相应数据与 big_vision 环境；本次没有下载模型大文件或运行训练。

模型保留一份原始投影参数，每次从它生成需要的大小。作者 README 提醒不要把多次缩放后的权重继续作为下一次缩放的来源，因为32→8→32通常不能恢复原始参数。当前公开 ImageNet-1k 默认权重链接标为1200 epoch版本，不能把它当作任意图中训练时长的复现结果。视觉权重也没有经过 CIR 验证；无线迁移需实现延迟轴上的投影与位置编码，并重新训练或适配。

### 学习重点：从响应变化提出设计，再用控制实验解释

本次选择“数学直觉怎样引出方法”与“实验控制怎样排除另一种解释”。作者没有从伪逆这个术语开始介绍设计，而是先问一个简单问题：输入和权重同时放大，原来的内积还能否保持？

§3.4 第一段先用非负输入说明，二维输入与核各放大两倍后，普通插值得到的 token 幅度可能约为原来的四倍。这提供了一个具体的失败原因：网络面对的投影响应已经改变。段末把需求限定为在没有信息损失时保持输入投影，紧接着一段讨论归一化的局限：它需要改变模型，而且没有精确保留原投影。

随后作者依次写出 resize 矩阵、响应误差目标和解。式2最小化 $\mathbb E[(x^T\omega-(Bx)^T\hat\omega)^2]$，使读者知道“正确缩放”要保留哪个量。上采样时，式3直接展示矩阵相消；降采样时，作者转而说明输入分布会影响解。补充 A.2（p1，式6–9）进一步把目标写成由 $\mathbb E[xx^T]$ 加权的二次型：在降采样问题中，各向同性输入的最优解可由标准伪逆得到，更一般的输入二阶统计量可能改变最优解。

提出方法之后，实验段没有立即让更小分块产生更多 token，而是同时缩放图像与分块，保持 $s=(224/8)^2=784$。因此 Fig.4 主要检查投影缩放方式，避免把结果直接解释成更长 token 序列带来的收益。它控制了 token 数，没有声称所有输入处理与投影计算成本完全相同。实际查看 Fig.4 和 Table12 后，448/16设置下 PI-resize 的52.3%与普通插值的12.8%可以精确对照；在严重降采样的56/2设置，PI-resize为10.3%，普通插值为25.5%。结果支持上采样时的保持能力，降采样仍需按信息损失与任务分布评价。

图4横轴把“输入大小/分块大小”成对写出，图注补上原始224/8模型，读者可以直接算出每个点的 token 数。补充表提供曲线数值，使论证不依赖肉眼估读。这些图表选择服务于控制变量；双栏位置与字体属于会议版式。

另一个不同用途见 §4.2（PDF p6，论文 p14501，Fig.8）：作者在8×8网格上微调，然后用24×24网格推理，ImageNet-1k top-1准确率从81.8%变为85.3%，增加3.5个百分点。这里节省的是额外训练，较长序列的推理仍需更多计算。它启发的是“适配时便宜一些、部署有预算时再用细粒度”，与 Fig.4 的固定 token 控制实验回答不同问题。

### 手算：普通插值改变响应，伪逆保留响应

以下是助手原创的一维例子，可理解为两个 CIR 实部采样的一个线性特征，幅度和权重均用任意单位。取

$$
x=\begin{bmatrix}2\\4\end{bmatrix},\quad
\omega=\begin{bmatrix}1\\2\end{bmatrix},\quad
B=\begin{bmatrix}1&0\\1/2&1/2\\0&1\end{bmatrix}.
$$

原始响应为 $x^T\omega=10$；插值后的信号为 $Bx=[2,3,4]^T$。若同样插值权重，得到 $B\omega=[1,1.5,2]^T$，响应变成 $2+4.5+8=14.5$。再按样本数比例乘 $2/3$ 也只有 $9.6667$，不能精确保留原值。

采用 $\hat\omega=(B^T)^+\omega=[0.5,1,1.5]^T$ 后，响应为 $1+3+6=10$。这里保留的是同一输入经过指定线性重采样后的一个投影，未生成新的物理带宽。

反过来，把两点平均成一个点，$D=[1/2,1/2]$。若需要的特征为差分 $\omega=[1,-1]^T$，原响应为 $-2$，但重采样输入只剩3，伪逆给出的权重为0。任何仅看到均值3的算法都无法对所有可能输入恢复该差分：输入 $[4,2]$ 也有均值3，原差分却为2。这是信息已被丢失的反例，不能通过调整输入核解决。

原创组网映射可以从固定256个 CIR 采样入手：每8点一块得到32个 token，每16点一块得到16个 token；忽略特殊 token 时，注意力成对项从1024变为256。这个4倍比值仅描述注意力矩阵规模，未包含投影、前馈层、内存和设备调度，不能称为端到端4倍加速。实际分块改变了各 token 覆盖的延迟范围，局部投影等式不能保证测距精度不变；需要在多分块训练中学习这种变化，并保留明确的物理延迟位置。

可研究的新条件是：同一网关的计算余量变化时，能否让一个 CIR 模型切换分块粒度，维持任务可接受的首径估计误差。最小比较包括固定粒度训练后直接换粒度、随机粒度训练加普通插值、随机粒度训练加 PI-resize，并用分别训练的固定粒度模型作参考。保持原始采样、任务标签与训练计算预算可比，分别测窄首径、邻近多径和低信噪比条件下的误差及设备延迟。沿用已有通信时限结果，新增检查接收之后的计算预算与估计质量；不存在本次已经测得的无线收益。

### 原创英文练习：先交代保持量，再引实验

下面两段由助手自拟，未引用作者原句，也未修改用户论文。

**差段：** “We resize the input filters to support different patch sizes. The pseudoinverse preserves all information and improves accuracy, as shown in Fig. X. Larger patches also reduce computation, so the same model can process CIR measurements at any resolution without losing ranging accuracy.”

诊断：没有定义要保持的量；把上采样时一个线性响应的等价扩成全部信息不丢失；同时改变分块和计算规模，使读者无法判断准确率变化来自哪个因素；最后把图像结果写成了无线结果。

**改段：** “Changing the patch size alters the input projection, even when the model retains the same Transformer weights. We therefore choose the resized filter to preserve the original projection response under a specified linear resampling operator. To test this mechanism separately from sequence length, we scale the input and patch dimensions together and keep the number of tokens fixed. We compare pseudoinverse resizing with ordinary interpolation and magnitude-based corrections under this controlled setting. For CIR measurements, the same construction motivates a flexible input projection, while the effect of coarser patches on first-path estimation remains an empirical question. We evaluate that effect at matched raw sampling rates and report both estimation error and measured inference time.”

改段把保持对象、控制变量、比较对象和迁移验证按顺序连接起来。**preserve the original projection response** 只在指定重采样关系及对应秩条件下用于等价主张；**separately from sequence length** 则要求实验真的固定 token 数。若无线实验改变了原始采样率或漏掉一段 CIR，就需重新说明输入信息变化，不能沿用这里的固定输入解释。

## RANPilot

Shiming Yu、Leming Shen、Jianing Zhang、Xin Li、Xianjin Xia、Yuanqing Zheng、Yaxiong Xie，*RANPilot: Making AI Functionalities Robust to Dynamic O-RAN Reconfigurations*，SIGCOMM 2026，284–300，[DOI 10.1145/3789240.3829146](https://doi.org/10.1145/3789240.3829146)。正式题名、会议、页码和七位作者由出版元数据核对，正文依据[作者公开的 17 页会议稿](https://xiaoming124.github.io/files/RANPilot_SIGCOMM26.pdf)，以下使用 PDF 页码。本篇首次收录，重点是**计划中的系统变更怎样进入训练数据，以及提前准备究竟缩短哪段时间**。

### 六句研究卡

- **问题**：新增小区或更换切换策略后，依赖旧网络数据的 AI 功能怎样快速恢复有效，而不等新网络运行很久才重新收集训练数据？（§1、§3。）
- **缺口**：旧数据加噪声可以增添波动，却没有表达新拓扑、共享接口和控制策略怎样改变用户关联与业务；纯变更后学习还要等待有用样本出现（§4.2、§6.3.1）。
- **观察**：运营者事先知道配置计划，现网已有站点与用户的测量轨迹，可用这些轨迹建立目标配置的轻量模拟，再把一部分准备工作放到生效之前（§4.1–4.2）。
- **方法**：构建抽象的 CU、DU、RU 及接口，回放未变部分的轨迹、调整变更部分并执行相应控制；随后扩充轨迹的时序变化，部署后再优先重放分布变化较大的片段（§4.2–4.4）。
- **证据**：QoE 预测的小区新增实验中，TenaxDoS 达到指定表现需 29 分钟，其中收集数据占 25 分钟；完整 RANPilot 在变更后用 1.7 分钟完成适应，约减少 94%（§6.3.1，p.10，图 16）。
- **边界**：这里的恢复计时从配置生效开始；目标是站点内已知计划的变更，依赖种子轨迹能代表当地环境，前置合成与训练成本另计，突然出现的新环境需要在线机制处理（§6.4、§7，p.12）。

### 重点一：数据要反映新规则如何改变动作

选择这一点，是因为论文并未将合成数据只写成“生成更多相似样本”。§4.2 先确定哪些部分是新计划的输入：拓扑、单元参数、相邻小区关系与控制策略。§4.2.3 建立系统骨架，§4.2.4 注入实际轨迹，§4.2.5 再加入共享接口与控制交互。每一步都给下一步不同的信息，读者可以理解为什么既要真实轨迹，也要目标配置。

实际查看 p.6 图 9：三段图从骨架、流量生成走向交互，接口行为与无线控制分别列出。正文说明未变单元可回放旧轨迹，新单元则依据新拓扑调整行为；切换策略的修改进入可执行控制逻辑。这样，图中的箭头表示会影响后续数据的动作，而不仅是“把数据传到下一个模型”。这套模拟抽象的是关键行为，未逐样本重做完整物理层波形。

**助手完成的最小例。** 设同一用户看到小区 A 的 SINR 为 10 dB、负载 90%，B 为 9 dB、负载 10%。旧规则选择最强信号，输出 A。自拟的新规则先保留距最强信号不超过 3 dB 的小区，再选负载较低者，输出 B。输入信号没有变，控制规则已经改变用户关联，后续队列和吞吐也可能随之改变。只在原轨迹上独立加噪声，不能保证生成这条“规则—关联—负载”的关系。该例未使用论文的实际策略参数，也未宣称已经模拟关联后的完整吞吐。

§6.3.1 用两个连续变更检验这条思路：先新增小区并使用基于 SINR 的切换，再改成结合负载的切换。图 15 保持 QoE 预测器结构相同，比较训练数据与适应方式；相同数据量的噪声扩充和跳过虚拟 O-RAN 的变体表现接近未适应模型。该比较给出了保留系统交互的理由。它没有把所有收益都单独归给某个网络层，虚拟系统、序列生成和在线学习仍有不同职责。

### 重点二：把恢复时间写成一条有起点的时间轴

精读 §6.3.1 的完整论证时，前段图 15 回答“新配置刚生效时，视频表现怎样”，随后段首转问“适应要付出多久”。作者先说明 AI downtime 从配置生效计时，到模型达到文中 Oracle 最佳表现的 95% 为止，再用图 16 把数据收集和模型训练分开。这一转折避免把初始 QoE 较好直接当成恢复过程已经结束。

小区新增的基线 29 分钟中，25 分钟用于收集足够数据。作者接着解释，新策略造成的变化集中在少量关键执行模式，整体特征对齐难以替代这些样本。消融按模块逐项加入：虚拟 O-RAN 使变更后的数据收集降至 7.9 分钟，加入元增强后为 2 分钟，再加入选择性在线学习后为 0.9 分钟；完整适应合计为 1.7 分钟。后三个数据收集时间属于不同变体，不能相加当作同一次运行的三个阶段。

实际查看 p.10 图 16，堆叠柱把收集与训练分开，并用两组颜色区分小区新增、切换策略修改。相同配置下比较堆叠总高，才能回答总恢复时间；比较柱内某一部分，才是在解释瓶颈。p.12 图 18 又单独列出变更前的数据合成与增强成本，其中增强约为 14–15 分钟。把两图连起来，得到的具体判断是：提前得到计划，使一部分工作不再阻塞变更后的服务恢复。

**助手已核算的时间例。** 假设新配置需要 20 分钟前置准备，生效后还需 2 分钟校准；提前获知计划的时间为 $L$ 分钟，准备可连续执行且残余准备必须先完成。则生效后的恢复时间为

$$
T_{\mathrm{post}}=\max(0,20-L)+2.
$$

若提前 30 分钟通知，变更后的等待为 2 分钟；若只提前 5 分钟，则为 17 分钟。两者总准备与校准工作都为 22 分钟。这个原创模型把“提前量是否足够”变成可检验条件，数值不是论文实测。论文 29 到 1.7 分钟的减少比例另算为 $1-1.7/29\approx94.14\%$，与约 94% 的表述一致。

### 原创英文段落训练

以下差段和改段由助手自拟，非原文或用户稿。

**差段：**

> RANPilot generates more data and reduces model training by 94%. It works immediately after any network change. Figure 16 proves that the method eliminates the cost of preparing a new model.

**诊断。** 合成数量替代了数据中必须包含的系统变化；恢复时间被写成训练时间；提前准备的前提与成本消失了。

**完整改段：**

> We first evaluate the predictor immediately after the planned reconfiguration to determine whether the prepared model is useful at deployment. We then measure recovery from the activation of that configuration to the specified performance threshold, separating data collection from model training. In the cell-addition experiment, the reactive baseline requires 29 minutes, including 25 minutes of data collection, whereas the complete system reaches the threshold in 1.7 minutes. The staged variants connect this reduction to configuration-aware synthesis, broader trace augmentation, and selective replay of live data. Figure 18 reports the preparation cost incurred before activation, so the result describes reduced post-change downtime under advance notice rather than removal of the total adaptation workload.

**改法与使用条件。** 两个段首分别问生效时表现和生效后恢复，数字紧跟自己的起止点；之后将模块对应到数据作用，最后用前置成本图补全时间轴。原文短搭配 **“by exposing the model to”**（§6.3.1，p.10）说明模型提前接触哪类配置，不宜改成已经保证未来表现。这里适合计划升级、模型预热与预先标定；没有提前通知的变更需另列观测和响应过程。

### 对四板 UWB 的具体新问题：已知排程将变，旧轨迹还能提前告诉我们什么

已有 10,000 轮每轮均在 100 ms 内收齐 300 条数据，其中 5,131 轮补发一次，4,869 轮补发 2–4 次。接下来若计划修改节点轮转次序或补发策略，新增问题可以是：**提前用现有日志重放候选排程，能否预测变更后需要的补发预算，还是关键损失取决于旧日志没有记录的接收状态？**本问题不要求当前系统先增加神经网络。

最小比较可固定四块板、每轮 300 条和物理层设置，准备两种候选排程。对每个候选分别做两种离线估计：只给旧日志增加随机丢包；保留接收重开、数据搬运和补发触发的事件依赖后再重放。两种估计使用同一批旧记录，并与之后独立采集的新排程结果比较首次缺失位置和最终耗时。若保留依赖能解释新排程中重复出现的缺口，就值得进一步建设事件模型；若排程改变同时改变了无线重叠或接收机状态，而日志无法描述这些变化，重放结果仍须由新的实测约束。

计划变更和环境突变应分开记录。例如已知下轮调整 A、B、D 的时槽顺序，可以提前准备；新增金属遮挡造成的传播变化则没有相同先验。这里也需先核对日志是否包含所需事件，缺失时仅定义应观测的量，不能用已有收齐统计代替事件轨迹。上述是新实验设想，未修改固件、未开展四板测试。

### 从这十篇提炼的四种具体做法

1. **在正确位置保留候选。** Tree of Thoughts保留中间解再选择扩展；Promptbreeder把成功案例变成新的候选指令。对应组网研究，可以保存“哪条观测先区分原因”的诊断过程，再形成新的检查策略；用新轨迹评价准确率与测量成本。它们改变搜索对象，不能用一次案例成功代替独立测试。
2. **先定义必须保持的量，再改变系统形式。** FlexiViT定义输入投响应，LogEI检查数值表示对优化过程的影响，Schedule-Free区分更新与评估参数。对应论文写法，应说明改变尺寸、尺度或训练进度时保留哪个数学对象，再用控制实验检查。这样读者能判断所谓兼容或稳定具体发生在哪一步。
3. **让粗信息支持一个明确动作。** XGate用粗检测定位校准结构，DragonFly与GRADE在感知流程中安排不同信息的作用。方法段可按“当前可获得什么—据此执行什么—还有什么待估”展开。每个模块的输出都应有下一步用途，实验则检查其对任务结果的实际贡献。
4. **把已知未来转化为现在可做的准备。** RANPilot让计划配置进入数据生成，SpaceSched利用未来系统条件安排任务。组网中可以先试已知排程变更的事件回放：旧轨迹加目标规则，预测新配置的缺失位置与处理时间，再与独立实测比较。报告时把前置工作、变更生效后的等待和总工作分开。

### 一段实验文字怎样连起来

以下为助手原创写作骨架，适用于计划变更的离线预测实验，未表示已经取得无线结果。

> We first test whether traces from the current schedule can predict behavior under the planned schedule. The comparison uses the same historical measurements, while changing how the target control rules enter the replay. We report the error in predicted completion time and the locations of missing records. We then remove the event dependencies to determine whether the benefit comes from preserving the sequence of receiver and retry actions. Finally, we measure preparation time before activation and the additional calibration required afterward, linking predictive quality to the time available to use the result.

这段依次给出实验问题、固定信息、变化部分、结果量、机制检验和部署代价。后续写用户论文时，先核对实际实验是否提供这些证据，再采用对应句子；没有进行的比较保留为实验计划。

### 可复用表达

**preserve the original projection response**：保留指定线性投影的响应；使用时要给出输入之间的重采样关系。原创例句：We resize the filter to preserve the original projection response under the chosen interpolation operator.

**before the configuration takes effect**：明确准备位于配置生效之前。原创例句：The gateway prepares the candidate model before the configuration takes effect and measures any remaining calibration afterward.

**use the same parent candidates**：为搜索算子提供可比起点。原创例句：We use the same parent candidates and validation traces to compare the two modification rules.
