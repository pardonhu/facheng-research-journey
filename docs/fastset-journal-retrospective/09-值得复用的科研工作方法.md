# 09 值得复用的科研工作方法

复盘不仅回答“下次别犯什么错”，还要回答“下次怎样更快做好”。作者在本次整理中进一步明确：“不止要避坑，还要积累有用的经验。”

下面整理交流中提出、使用或值得继续落实的方法。具体收益依任务而异；这些是经验和实施建议，不把提出过的办法一律说成已经验证有效。

## 1. 先建立一条完整的小流程，再扩大规模

先让少量代表性任务从输入一路走到图表和结论。这样能及早发现问题出在模型、数据、指标、文件组织还是表达。

**复用方式：** 新模型先跑小规模加载、更新和评价；新仿真先验证少量场景；新报告先做一张有数据来源的完整结果图。小流程通过后复用实现，扩大输入和任务数。

**留下的资产：** 最小运行入口、一份有效配置、一套完整输出示例和必要回归。

## 2. 公共实现集中维护，实验差异用配置表达

把模型、数据处理、训练评价和画图拆成共享模块，薄入口选择配置。这样修一个实现问题，不必在每个实验目录里重复改。

**复用方式：** 场景、方法、预算等变化放在配置；每次运行记录代码与配置版本，结果单独保存。已有实验依赖旧实现时保留对应版本，不能让共享代码更新悄悄改变历史结果的含义。

**留下的资产：** 可复用模块、配置示例、结果目录约定，而不是几十份近似但不一致的代码。

## 3. 一次计算留下足够信息，支持多次分析

保存每个必要评价点的原始计数、指标和成本，可以支持后续换横轴、比较停止规则、计算评分敏感性，而不必全部重跑。

**复用方式：** 先判断后续哪些问题能够从同一批结果中回答，再决定记录粒度。额外记录本身有成本，尤其在正式计时时，应采用不干扰测量的方案。

**留下的资产：** 有单位的 CSV、状态对应关系、必要 checkpoint，以及可重新生成统计结果的代码。

## 4. 用小诊断筛选“大实验到底值不值得跑”

出现意外结果时，最有价值的下一步通常是能区分原因的对照。例如先确认初始表现，再看适应增益；先比较同一实现的输入和输出，再讨论结构是否更优。

**复用方式：** 把两个最可能的解释列出来，找一个成本低、两者预测不同的检查。诊断结果再决定是否需要扩大预算、增加重复或更换方案。

**留下的资产：** 问题、检查、观察和处理结论。以后遇到相同故障有入口可查。

## 5. 把硬件资源变成可持续执行的任务队列

多卡的收益来自准备充分、独立任务不断接续、失败能恢复、结果及时回收。单纯增加 SSH 窗口和启动进程，不能保证整体更快。

**复用方式：** 按依赖准备任务，按资源需求派发，按预计剩余工作量平衡负载。训练可分散，正式计时遵守统一环境。

**留下的资产：** 见[远程服务器与多 GPU 实验调度](08-远程服务器与多GPU实验调度.md)中的资源表、状态机与汇报模板。

## 6. 把异常发现转化为新认识

新条件下旧方案不再最优，或某个阶段提前满足目标，可以成为理解方法的线索。先排除直接错误，再研究它揭示了什么分工、成本或适用条件。

**复用方式：** 依次整理“原先怎样评价—新观察是什么—哪项机制或流程体现了这个现象—还需什么证据”。结论可以改变，原始结果保留。

**留下的资产：** 能写进方法解释和实验分析的发现，而不只是一组新的最优参数。

## 7. 先完成代表性图，再统一整篇样式

一张主性能图、一张时间图和一张多子图足以暴露多数风格与尺寸问题。作者认可后，再把样式应用到全文，比逐图反复试错更省时间。

**复用方式：** 固定方法名称、颜色、线型、marker 和最终尺寸；数据与样式分开；用论文实际显示尺寸验收。PPT 也先做代表性的内容页，但重新按演示场景安排字号和信息量。

**留下的资产：** 可编辑绘图代码、风格入口、数据来源和已经确认的样张。

## 8. 按段落和论证链改稿

逐段讨论“这一段要表达什么、证据是什么、与前后怎样衔接”，能保留作者思路，同时修正真正需要修改的内容。

**复用方式：** 先改影响主线的定义与结论，再处理实验解释，最后润色和排版。一次只确认一个有边界的部分，保持主稿唯一；不是每次反馈都全文重写。

**留下的资产：** 稳定的术语、段落职责和结论—证据对应关系。它们还可以用于摘要、SoD、邮件和汇报，分别调整篇幅与细节。

## 9. 每次交付都减少下一次的启动成本

成果除了当前图表或论文，还应包括接手者需要的来源、入口和状态。重启、换机器、换助手时，能够继续，而不是重新考古聊天。

**复用方式：** 保存唯一主文件、有效决定、已完成结果、下一步和明确关闭的事项。公开库存经验与模板；私有工作区存机器、数据与访问配置。

**留下的资产：** 一份短交接、可执行入口和可追溯结果。重点是让下一次少问重复问题。

## 10. 以后怎样继续积累

新增经验用五项记录即可：

| 项目 | 要回答的问题 |
|---|---|
| 场景 | 在什么任务和约束下用过？ |
| 做法 | 具体怎样执行，别人能否照做？ |
| 依据 | 已实际使用、测过收益，还是待验证建议？ |
| 适用条件 | 什么情况下值得复用，什么变化需要重审？ |
| 可复用资产 | 留下了代码、模板、配置、样张，还是判断方法？ |

不要把未经比较的办法写成“效率提高很多”，也不要只存一条“以后注意”。好的经验，应当让下一次任务少走一步弯路，或直接复用一份可靠成果。

## 11. 从反复追问提炼缺失的解释

后续[RFDT PPT 协作](../rfdt-ppt-retrospective/README.md)中，同一方法反复被问“为什么、怎么算、哪些已知”，提示缺失的是计算与问题之间的联系，而不只是词语不够通俗。可复用资产是方法问题链、公式来源卡与实验证据卡，见[检查表](../rfdt-ppt-retrospective/checklist.md)。用户追问可用作理解检查，但不能把用户承担了大量澄清工作本身记为高效协作。
