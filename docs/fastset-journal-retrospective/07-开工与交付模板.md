# 07 开工与交付模板

以下模板按需要取用。小任务用几句话即可，不要求每次填完整套表。它们服务于明确理解和减少返工，不是新增审批流程。

## 1. 开工时：用五行锁定目标

```text
要解决的问题：
这次要交付什么，放在哪里：
必须保留的条件或原有内容：
哪些关键决定已经确认，哪些仍缺依据：
做到什么就结束：
```

例如，“调整三张图的字号”不需要重新检查实验设计；“比较两种算法谁更快”则必须先说明相同任务、输入和计时边界。

## 2. 发现结果异常：先列差异，再补实验

```text
观察：实际发生了什么？
预期：依据是什么？
已确认相同的条件：
实际不同或尚未确认的条件：
最小下一步：做哪项检查能区分当前最可能的解释？
检查后决定：继续、修复、接受结果，还是需要用户决定？
```

没有证据时用“可能”，查明后给出对应记录。不要以“全面复核”代替可回答问题的下一步。

## 3. 要改变设置：只说明真正的变化

| 项目 | 旧设置 | 新设置 | 为什么变 | 影响哪些结论/文件 |
|---|---|---|---|---|
| 待填写 |  |  |  |  |

已明确授权的变更直接执行。尚未确定且会改变科学含义的选择才需要询问；配色微调、普通代码修复等可逆细节不反复请求许可。

## 4. 写论文或做 PPT：先连上结论和证据

| 想让读者明白什么 | 对应证据 | 这张图/这段话承担什么任务 | 需要交代的条件 |
|---|---|---|---|
| 待填写 |  |  |  |

写不出第一列，先别加页面。第二列不存在，不能靠语气把结论写强。条件很长时，将公共条件放在 setup，局部差异留在对应实验。

## 5. 进度汇报：说清当前状态

```text
已完成：结果与文件入口。
正在运行：任务、资源、真实进度。
下一项：依赖是否齐全，何时可执行。
阻塞或变更：原因、已处理什么、还差什么。
需要作者决定：仅列确实需要选择的事项；没有则不列。
```

没有实际进程、调度器或检查记录，就不能说“持续监控中”。估时说明根据当前速度还是历史经验；不要伪装成确定的完成时间。

## 6. 交付前：按任务类型选最少的检查

**实验或统计：** 对象与单位明确；条件和停止规则正确；输出能追溯；结论没有超过证据；没有漏报失败或未完成部分。

**论文：** 改的是指定主稿；保留要求保留的内容；图文数值一致；引用有依据；编译后的页面已看过。

**图表：** 数据没有因美观而改变；图例、轴、标记在最终尺寸可读；标签不遮挡；主稿引用的是新图。

**PPT：** 每页有明确任务；标题与证据对应；投影尺寸可读；交付格式符合要求；讲述顺序连贯。

**仓库文档：** 链接有效；规则与建议区分；不含凭据和私人信息；提交只覆盖授权范围；远端确实收到。

## 7. 交接：让接手者不必重读聊天

```text
唯一主文件/结果目录：
当前有效协议或决策：
已经完成且不需重做的内容：
正在运行的任务与负责人：
已取消、已关闭、明确不再处理的事项：
下一步及其依据：
恢复入口与实际检查方法：
```

## 8. 一分钟自检：我是不是又在犯同一种错？

- 我是否用一个熟悉的词掩盖了定义不清？
- 我是否悄悄替用户决定了研究条件？
- 我是否在追一个漂亮数字，而不是实际目标？
- 我是否把猜测当解释，把局部通过当整体正确？
- 我是否在用旧决定、改错文件，或重启已关闭事项？
- 下一步是否真的必要？
- 我是否打开过用户最终会看到的成品？

遇到其中一项，先修对应环节；不要默认整项工作必须推倒重来。

## 9. 换个领域，检查动作是否仍然明确

以下是假设例子，不是本项目的实验记录。

| 新任务 | 容易重犯的模式 | 马上应该做什么 |
|---|---|---|
| 比较机器人策略的学习速度 | 把控制 step 和 episode 混用；只比较次数 | 明确一次交互包含什么，按共同任务比较数据量和成本 |
| 比较新旧材料的强度 | 配方与加工温度一起改变，却只归因于配方 | 先列条件差异；现有数据只能支持整套工艺比较时，就按整套工艺表述 |
| 给导师做一份系统研究 PPT | 只放最漂亮的结果；直接缩小论文图 | 先写每页要回答的问题，选对应证据，再按投影尺寸重排 |
| 修复一份已有统计报告 | 顺手重构全流程，旧图与新结论并存 | 限定受影响的计算与图表，从最终报告入口检查更新是否生效 |

如果一条经验换个领域后只剩“认真一点”“多检查”，它还没有提炼到位；应改写成可以执行的判断或动作。
