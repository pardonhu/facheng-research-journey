# 06 复盘依据与偏好台账

本台账只记录支持复盘的必要依据，不公开原始聊天、机器信息、私人署名沟通和未发表实验结果。引用来自作者在本次交流中的指示；核实范围来自本地协议、修复报告和修改记录。

**责任说明：** 助手应为理解、执行和交付中的错误负责。但不能为了显得反省深刻，把作者提出的疑问编造成已经确认的事故。下面分别记录。

## 2. 有记录支持的技术与流程案例

| 案例 | 核实到什么 | 应学到什么 |
|---|---|---|
| 确定性设置与随机数初始化顺序 | 修复报告记录了原错误复现、显式 seed 初始化和独立回归；没有靠关闭确定性绕过 | 排查实际调用顺序，修根因，并保留针对该故障的最小回归 |
| 不同层次的等价检查 | 记录分别涉及结构、单步计算，以及不同环境下的连续运行 | 每个“通过”必须附检查范围；一个层次的通过不能代替另一个层次 |
| 时间定义变化 | 存在旧计时协议及后来确认的常驻系统计时协议，部分统计由不同来源组成 | 合并数据前检查边界；组合估计与同一次连续实测要区分 |
| PEBS 与停止规则变化 | 历史协议先后采用不同预算、评价时点和用途 | 指标名称相同不代表实验含义相同，要记录有效版本 |
| 对已复核事项的关闭 | 有按作者转达的另一会话确认关闭议题、同时保留原始记录的说明 | 尊重关闭决定；不反复启动复核，也不伪造替代证据 |
| 最小改稿与版面修订 | 修改记录包含局部改稿、编译检查，以及图文间距和顺序修订 | 局部编辑、编译成功和最终排版是不同验收项 |

公开台账不发布日志中的具体性能数字，也不据此重新评价论文方法。需要定位项目原记录时，在原项目内查阅；不将工作机绝对路径作为本仓库的依赖。

## 3. 只能记为质疑，不能写成定论的事项

作者曾问过：是否读到了已适应的模型、测试数据是否与预训练数据相同、显存没有占满是否意味着没有训练、某次速度下降是否来自并发任务。

这些问题都值得定位，但仅凭问句不能认定发生了数据泄漏、错误 checkpoint、GPU 未运行或资源争用。本复盘据此提出“确认对象、核对来源、检查实际进程”的动作，不声称这些原因都已被证实。

同样，某个模型结果出乎预期，不自动证明实验有误；用户想看到某个排名，也不意味着可以按这个排名筛选结果。

## 4. 可长期沿用的明确偏好

| 偏好 | 后续如何执行 | 不应扩大成什么 |
|---|---|---|
| 说人话，先回答具体问题 | 结论在前，说明理由和必要证据；少用抽象术语和套话 | 删除所有技术限定，或把推测写成事实 |
| 保留准确的技术单位 | iteration、epoch 等按原意使用，不笼统写“轮” | 每句话都堆英文 |
| 最小修改，尊重原有表达 | 未受新结果影响的背景和方法尽量保留 | 发现真实矛盾也不修 |
| 主动完成已授权的工作 | 排除依赖、处理普通失败、检查交付，避免反复请示 | 自行改科学协议或占用别人资源 |
| 汇报要具体、完整 | 说明完成、运行、排队、阻塞及下一步；给出对应文件 | 用大量日志代替判断 |
| 论文图可编辑、可复现 | 保留画图代码和数据来源，交付最终引用版本 | 为美观改数据、虚构未测部分 |
| 术语、图例和缩写一致 | 首次给全称，后文统一；按用户指定名称修订 | 把一个项目的命名推广到所有研究 |
| 中文邮件首次中文接英文 | 首次写“中文（英文）”，后续按语境使用英文 | 把邮件风格机械搬进英文论文 |
| 成品要紧凑、清楚 | 检查真实尺寸、图文顺序、遮挡、留白和可读性 | 为塞满页面牺牲信息组织 |

## 5. 必须记录覆盖关系的要求

| 事项 | 交流中的变化 | 迁移规则 |
|---|---|---|
| 修改目标 | 曾扩展到更多实验，后来多次收缩、暂停或交给其他会话 | 最新有效范围优先，不按历史最大任务集执行 |
| 时间统计 | 从训练耗时转为模型常驻、预热后计入输入处理与训练 | 新项目重新定义测量边界，不能套用本次数值 |
| seed 与重复 | 默认设置后来为特定实验增加重复 | “默认”允许明确例外；不能把补测当作全局变更 |
| 期刊差异说明 | 先要求放在 SoD，后来导师要求 Intro 也简短交代 | 更新局部要求，不在全文重复版本差异 |
| 实验设置顺序 | 先提出硬件开头，后根据反馈将其后置 | 按当前文章逻辑和最新反馈组织 |
| 配色与背景 | 色板试用后明确要求 PDF 无背景填充、轴文字黑色 | 保存最终约定；不能重新套回旧主题 |
| 页数与布局 | 曾希望扩到更长，后来要求回退并改善图文安排 | 页数服从投稿限制和阅读质量 |
| 资源使用 | 共享卡权限、优先级和停派条件多次变化 | 运行前查当前授权和状态，不继承无限权限 |

具体 GPU、模型宽度、训练预算、字体和图编号属于项目设置，不作为跨领域研究的科学规则。正文删去某段分析，也不等于授权删除原始结果。

## 6. 复盘建议与原话分开

八种错误模式、轻量任务卡、结论—证据对应表，以及将最终尺寸检查迁移到 PPT，都是本次整理提出的执行建议。它们参考作者反馈和原有科研指南，不冒充作者已经逐条批准的新制度。

此次最直接的一项反省发生在整理本身：初稿偏向记录实验操作，作者希望的是跨领域防错。修正办法是让正文围绕定义、决策、证据、状态和交付组织，项目细节退到本台账。以后收到“总结经验”类任务，应先辨认用户要的是操作复现、个人偏好，还是可迁移的判断方法。

## 7. 补充：经验积累也是交付目标

作者随后明确：“不止要避坑，还要积累有用的经验。”据此新增 08 远程调度和 09 有效工作方法。经验应说明具体做法、适用条件和可复用资产；实际用过的办法与待落实建议分开，不把建议包装成已验证收益。
