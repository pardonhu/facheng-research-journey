# RFDT 组会 PPT 协作复盘：让听众跟得上方法，而不只是看见内容

整理日期：2026-10-23。

## 这次完成到哪里

本次围绕论文 *Physically Accurate Differentiable Inverse Rendering for Radio Frequency Digital Twin* 准备组会汇报，经历了提纲、详细稿、样张、完整中英文 PPT、局部改稿、技术问答与回退。用户最终评价是有可取之处，但仍未达到完全可用。这里记录进展、失败和下一次可复用的方法，不把文件成功导出或某次局部认可当作整套汇报验收通过。

依据分为三类：**明确要求**来自本次用户反馈；**执行记录**来自会话中的操作与检查；**复盘建议**是据此提出、仍需后续验证的做法。论文技术细节只作为解释错误的例子，不作为已复现算法或正式审稿结论。公开记录不包含私人项目资料、原始聊天和本机路径。

入口：[组会指南](../../如何制作组会.md) · [评价标准](../../如何评价一份工作.md) · [图表与 PPT 交付规范](../fastset-journal-retrospective/04-图表与PPT交付.md)。

## 1. 最大的问题：有模块、有公式，却没有解释作者为什么需要它

**明确要求与实际反馈：** 方法是汇报重点；用户多次反馈 Challenge 1 听不懂。把标题改成“边缘过渡”“路径权重”，或者增加公式，并没有直接解决问题。

### 失败的组织方式

先列候选路径、UTD、衍射、梯度，再说它们合起来构成系统。第一次接触工作的听众不知道每一步解决什么，也不知道为什么上一步还不够。

### 更值得复用的组织方式

沿着问题链讲：

> 具体场景中哪里出了问题 → 原方法为什么失效 → 作者先怎么改 → 这一步还留下什么问题 → 再怎样解决 → 回到完整系统。

本例中，先区分“反射点跨出自身表面”和“路径被另一物体挡住”；再解释保留候选路径、计算边缘场贡献、处理额外遮挡，最后回到原论文系统图。用户要求把自己改过的对比页放回第一类问题的解释位置，而不是直接删掉重做。

**适用条件：** 作者的方法确有依赖关系时使用。不要为了讲故事虚构“作者先尝试了某方案才失败”的研发历史；讲的是技术必要性，不是未经证实的发现顺序。

**下次检查：** 每页必须能回答“为什么到这里需要这一步？”和“下一页要补什么？”若只能复述模块名，说明还没讲清。

## 2. 核心想法、优化目标、具体贡献要分开

**执行记录：** 初稿用“优化信号一致性”概括核心想法，用户指出偏离了重建任务。更清楚的任务叙述是：从初始场景出发，经可微 RF 仿真与实测响应比较，利用梯度逐步更新场景参数。

- **目标：** 希望得到什么，如恢复目标形状。
- **机制：** 怎样利用输入获得输出，如可微逆渲染的迭代闭环。
- **目标函数：** 用什么误差驱动更新，如模拟与实测信号的差异。
- **技术贡献：** 为了让闭环真正可用，解决了哪个难点。

不能只把“最小化 loss”当作核心想法；也不能把一张验证图直接叫作贡献本身。贡献是方法，图是支持方法的证据。

## 3. 系统模型必须落到具体变量

**明确要求：** 先交代角色、输入、输出和假设，再讲方法。“initial scene”“Model”这样孤立的标签不够。

用下面的表做备稿，而不是把所有内容堆在一页：

| 类别 | 必须回答 |
|---|---|
| 固定配置 | 设备位置、发射设置等哪些已知，哪些保持固定？ |
| 实测数据 | 接收的是原始采样、频谱、RSS，还是其他表示？ |
| 待估参数 | 几何、姿态、材料中，本任务具体优化哪些？ |
| 初始化 | 待估参数从什么暂定值开始？ |
| 中间量 | 路径、角度、电场等怎样由当前参数计算？ |
| 输出 | 最终估计什么；与当前模拟响应有什么区别？ |

真实值未知，但当前 iteration 有暂定值，可以用它做一次前向计算。说清这点，比反复重复“逆问题”更有效。

示意图中移动接收机，与优化中修改网格，可能触发同类边界事件，但不意味着两者的梯度完全等价。必须交代示意变化与实际待优化变量之间的关系。

## 4. 公式先解释“算什么、从哪里来”，再解释符号

**明确要求：** 公式使用原论文截图、不带编号；空间允许则解释符号，不够时优先解释物理含义。截图要求属于本次明确偏好，下一次可被新要求覆盖。

推荐按以下顺序备稿：

1. 这个式子解决当前哪一个问题？
2. 输入中哪些是固定配置、哪些是当前估计？
3. 哪些量是计算得到的中间结果？
4. 结果乘到哪里、加到哪里，改变什么物理量？
5. 公式是经典理论、本文推导，还是实现近似？

**本次暴露的问题：** “入射场 × 系数 × 衰减和相位”虽然字面正确，用户仍不知道这些量怎样获得。应进一步解释：先计算波到达边缘时的场，再计算边缘朝接收机方向的衍射，再计算这段传播的衰减与相位。

### 不要把术语转换成错误的直觉

- 复值权重会改变幅度和相位，不一定是 0 到 1 的实数比例。
- 物理过渡函数不等于“板外越远就越趋于零”的软掩码；要核对其参数定义和极限。
- 场连续不自动推出处处可微；两项相加本身也不是可微性的证明。
- 自动微分对已有表达式求导，不能自动纠正物理模型遗漏。
- 经典理论公式有来源，不代表本文采用它的全部连接步骤已核实。

**执行记录：** 对权重的早期解释过于确定，后续问答才区分了过渡函数、局部权重与完整衍射系数。没有完成源码复现，因此实现细节仍应标为“当前材料未充分核实”，不能上升为“已证明论文错误”。另一次把这些解释写入页面的修改被用户要求回退，不能把该页当作已经认可的模板。

## 5. 每组实验单独建立证据对应关系

**明确要求：** 主要性能、两个应用都必须有数据结果图与分析，不能只有系统示意图。

| 每项实验需要的信息 | 防止什么误解 |
|---|---|
| 仿真、实测或二者结合 | 把仿真 TX 当成现场 Wi-Fi AP |
| 设备及其作用 | 把计算用 GPU 当成测量设备 |
| 真值／参考如何获得 | 把有限差分、RGB-D 几何、RSS 实测混成同一种真值 |
| 对比方法的原理与版本／配置 | 把某个配置的限制推广到整个软件 |
| 指标、单位、坐标轴 | 把顶点误差当纵向误差，把误差曲线当 CDF |
| 图中结果与正文数值 | 将示意图当性能证据，或从图估读不存在的精确数值 |
| 观察与原因解释 | 把作者解释或我们的推断写成图直接证明的事实 |

本例中，梯度参考来自仿真有限差分；自采形状重建使用 RGB-D 参考；通信响应用 RSS 实测。外部数据集的参考来源要另外核对。具体设备、频率、距离、样本数不能跨实验挪用。

### 一张图先读坐标，再说结论

- 梯度图：说明对哪个参数求导；变化率图不是改变参数后的信号图。
- 小提琴图：宽度表达密度，不是普通柱状图的宽柱。
- 射线预算—误差曲线：向右移动意味着需要更多预算，不是 CDF 的右移。
- 多子图：逐一确认各子图的任务，不能给整张图套一个只适用于其中一半的结论。
- 误差中位数、均值、最大值和某些样本超过阈值不能混用。

### 密集仿真图不等于密集实测

少量测点可用于校准或检查；细粒度覆盖热图可以来自大量仿真查询点。图像分辨率不等于测量覆盖率。还要查校准点与测试点是否独立；未说明时只记“未说明”，不推定已经泄漏或已经验证泛化。

### 图文不一致时不替作者修数据

本次发现 Figure 8 中某基线的 SSIM 标注与正文不同。采取的处理是页面数值与所展示原图一致，另记正文差异，不修改原图数字。这个处理是执行记录，不表示数据冲突已经解决。

## 6. 评论只保留真正值得讨论的部分

**明确要求：** 依据《如何评价一份工作》独立评价，选择突出贡献和关键局限，不机械列全维度；用户用“motivation 好”举例，不等于用户真的赞同该判断。

先区分问题、模型条件、方法深度与证据，再选少量值得讲的判断。已有理论的采用与本文新构造的贡献要分开。学习启发具体到下一步可验证的事情，例如校准传播后比较布局或链路质量；同时指出迁移需要满足的模型条件。

不能把作者的两项独立应用拼成未验证的端到端系统，也不能把相关应用成功当作新研究场景已经验证。公开记录不写私人合作方、项目约束或未授权数据。

## 7. 页面风格：删赘词，不删因果和条件

**明确要求：** 英文页面以 point 为主，少量文本框，用字号、加粗、颜色和原生段落列表表达层级；避免花哨字体、过多框线、满页句子与密集注释。方法页与结果页先做样张，认可后再扩大。

可将冗余的“reported convergence within …”压缩为“convergence within …”，但保留必要条件、数值、基线与单位。来源和范围用短标签或紧邻证据表达，不能因追求简短而把报告值写成我们独立实测值。iteration、epoch 保留精确术语。

本次使用原论文图及原 caption，公式不截标号；不自行重画或平滑实验数据。完整 caption 导致图片过小时，拆页或重排，不靠缩小全页文字解决。作者信息包括一作、通讯作者／导师、实验室与近期成果；导师或共同作者不自动等于通讯作者，角色须核对。

**适用边界：** 1–2个文本框是排版方向，不是比理解更重要的硬指标。此次中英文与讲稿约定、字体大小、截图方式都以当前指令为准，不能变成所有任务的永久格式。

## 8. 用户手改后的 PPT 必须当作当前主稿

**执行记录：** 会话中页数多次变化，用户手改过正文、图片和顺序；请求回退时，检查发现其他页面已经有新编辑。最终只恢复指定页面，而非整份旧文件覆盖。

以后修改已有成品时：

1. 从磁盘读取当前主稿，按标题、内容确认目标页，不能只记历史页码。
2. 修改前保存可恢复快照并记录文件校验值；写入前检查文件是否被外部改动。
3. 限定修改页与对象，比较其他页的文本、图片、关系和备注；“讲稿不动”也必须核对。
4. 用户文件未保存或被占用时，再要求保存关闭；没有实际阻塞不反复索要确认。
5. 回退先确认其后是否有新编辑；有则局部恢复，保留用户后续修改。
6. 页数、顺序改变后同步检查 PDF、预览、索引及页码引用。

PPTX 的图片关系、幻灯片部件名、备注关系都需要保持有效。局部修改优先在当前包内做；不为了一个页面问题用旧生成脚本重建整套稿件。

## 9. 导出成功与内容验收分开

**执行记录：** 实际导出后曾发现公式与正文重叠、截图混入上一行字、caption 挤压结果文字；边界检查也报告过已有形状越界。这说明仅检查文件可打开、页数一致或 shape 边界不够。

需要分别报告：

- 文件与关系有效、页数一致、备注保留；
- 实际导出后的修改页是否存在重叠、截断、字号过小；
- 解释是否能让第一次接触论文的人复述；
- 哪些问题尚未解决、哪些页面并未重新验收。

检查脚本发现错误时，应诊断并修复或明确保留原因，不能只降低断言后仍声称全部通过。用户没有授权处理的已有问题可记录，但不要借机改无关页面。图文与讲稿未同步的状态也应标明；用户要求仅改页面时，不自动重写讲稿。

## 10. 下次任务的最短执行流程

1. **读当前输入：** 指南、参考 PPT、论文与官方项目页；确认当前主文件和本次修改范围。
2. **先形成理解：** 写系统输入输出表、方法问题链、公式来源表、实验依据表。
3. **先做可审阅内容：** 逐页写问题、point、图或证据、下一页为何出现；完成一张方法页、一张结果页样张。
4. **逐段完善：** 沿问题链改方法，沿证据链补实验，最后精选评论与研究关联。
5. **成品检查：** 在当前主稿上局部改动，导出并检查真实显示；新改动有快照、可局部回退。
6. **记录边界：** 对话中解释过不等于页面已更新；页面更新过不等于用户认可；通过技术检查不等于完全可讲。

可直接复用的备稿表见[检查表与记录模板](checklist.md)。这套流程仍需后续任务验证，不承诺已消除全部返工。
